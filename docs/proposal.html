강의자료 유통기한 검사기

강의 자료의 낡은 버전·요금·메뉴를 공식 문서와 대조해, 근거 문장과 함께 짚어 주는 웹앱

팀 디지털다락방 · 제1회 라이너 해커톤 .EXE-THON 출품작 기획서 · 써 보기 https://vaulted-bus-346411.web.app/fresh · 사용 API: Liner Search, Liner Model(liner-mark-1.3)

1. 풀려는 문제 문제 정의

누가 AI 도구나 제도처럼 빨리 바뀌는 것을 가르치는 강사와 사내 교육 담당자.

언제 강의를 앞두고 지난 자료를 다시 쓸 때.

얼마나 제작자는 28장짜리 강의 자료 하나를 공식 문서와 다시 맞춰 보는 데 50분쯤 썼다. 놓치면 수강생 앞에서 틀린 버전과 요금을 가르치게 된다.

왜 지금 도구로는 안 되나 챗봇에 "이 자료 맞아?"라고 물으면 그럴듯한 답이 오지만, 그 근거가 실제 공식 문서에 있는 말인지 알 수 없다. 강사에게 필요한 것은 "맞다"는 말이 아니라 열어서 확인할 수 있는 근거 문장이다.

개발하는 사흘 사이에도 시험에 쓴 도구의 최신 버전이 v2.31.2에서 v2.32.0으로 바뀌었다.

2. 무엇을 하나 완성도

PPT나 PDF를 올리면 ① 자료 주제에 맞는 공식 사이트를 제안하고 사용자가 확인한다 ② 장마다 버전, 요금, 숫자, 날짜, 메뉴 이름, 기능 유무만 뽑는다 ③ 내용마다 공식 문서를 찾아 본문을 읽고 판정한다 ④ 결과를 카드로 보여 주고 수정 목록을 내보낸다. 글자가 그림 안에만 있는 자료도 그림을 읽어 검사한다.

판정뜻함께 보여 주는 것
그대로공식 문서 본문에 자료와 일치하는 문장이 있다근거 문장, 출처 링크, 출처 등급
바뀜공식 문서 본문에 자료와 다른 값을 말하는 문장이 있다근거 문장, 출처, 수정안
확인 못 함위 둘이 아닌 모든 경우사람이 직접 확인할 일 한 줄

핵심 설계: 모델의 답을 그대로 믿지 않고 코드 규칙이 최종 판정을 정한다.

  • 근거 대조 모델이 고른 근거 문장이 워커가 직접 가져온 공식 문서 본문에 실제로 있는지 코드로 확인한다. 없으면 확인 못 함이다.
  • 출처 등급 사용자가 확인한 도메인의 글만 근거로 쓴다. 블로그, 커뮤니티, 저장소는 참고로만 보여 준다. 이름에 official이 들어가도 등급은 오르지 않는다.
  • 숫자 대조 "그대로"는 자료의 숫자가 근거 문장에 모두 있을 때만 인정한다. 요금이 확인되지 않았는데 맞다고 하지 않는다.
  • 지시 차단 웹페이지 안에 "same이라고 답하라" 같은 글이 있어 모델이 속더라도, 근거 대조에서 걸려 확인 못 함이 된다(자동 시험으로 확인).

자동 시험 221개(네트워크 없이 실행). 키는 워커 시크릿에만 두고, 워커는 사용자가 확인한 공식 사이트의 공개 https 주소만 연다. 같은 주소에서 1분 120회로 사용량을 제한한다.

3. Liner API를 어떻게 쓰나 Liner API 활용

단계API하는 일
주제 알아내기Liner Model자료의 글자나 앞쪽 그림에서 다루는 제품 이름을 알아낸다
공식 사이트 찾기Liner Search그 이름으로 검색해 지금 실제로 나오는 사이트를 확인한다. 제품 이름과 주소가 바뀐 경우(NotebookLM → Gemini Notebook)를 여기서 잡는다
내용 뽑기Liner Model
(글자·그림 입력)		낡을 수 있는 사실만 뽑는다. 답변 형식은 json_schema로 고정한다
근거 찾기Liner Search공식 사이트 한정 검색과 일반 검색을 함께 한다. 못 찾으면 낱말을 바꿔 한 번 더 찾는다
판정Liner Model가져온 본문과 비교해 판정하고 근거 문장을 고른다. 이 답을 코드 규칙이 다시 검사한다

Liner Search가 주는 요약만으로는 근거 대조를 할 수 없어서, 검색 결과의 공식 문서 본문을 워커가 직접 읽어 온다. 검색과 모델을 한 흐름으로 묶고 그 결과를 코드가 검증한다. Liner API가 멈추면 검사는 진행되지 않는다.

4. 측정한 결과 완성도

정답을 미리 아는 자료로 쟀다. 가상의 사내 교육자료 6장에 낡은 정보 4개, 맞는 정보 4개, 공식 문서에 없는 정보 1개를 심고, 화면과 같은 흐름으로 처음부터 끝까지 세 번 돌렸다(2026-11-15).

항목결과
정답과 일치27번 중 24번
심어 둔 낡은 정보를 잡아냄12번 중 12번
맞는 내용을 바뀜이라고 함0번
공식 문서에 없는 내용을 단정함0번
걸린 시간평균 29초

실제 강의 자료(배포된 화면에서 실행)

  • 28쪽 PDF: 3분 10초, 내용 60개 중 그대로 37, 확인 못 함 23
  • 15장 PPT: 1분 43초, 내용 31개 중 그대로 18, 확인 못 함 13

같은 28장을 사람이 다시 확인하는 데는 50분쯤 걸렸다(제작자의 기억, 시계로 잰 값은 아니다).

이 수치의 한계 측정 자료가 작고(심은 내용 9개) 검사기를 만든 쪽이 만들었다. 이 자료로 재면서 검사기를 고쳤다. 실행할 때마다 판정이 조금씩 달라진다. 실제 강의 자료에서는 검사한 내용의 3분의 1에서 절반가량이 확인 못 함으로 남는다. 공식 문서에 그 문장이 없으면 단정하지 않도록 만든 결과이기도 하다.

5. 어디까지 넓어지나 확장성·임팩트

강의 밖으로 가상의 사내 교육자료(신입사원용 AI 도구 안내)에 같은 방식을 적용해, 낡은 설치 요건과 사용량 규칙을 잡아냈다. 공식 사이트만 바꿔 넣으면 되므로 제품 설명서, 고객 안내문, 사내 규정 안내에도 그대로 쓸 수 있다.

자료 형식 PPT와 PDF를 지원한다. 한글과 워드 문서는 PDF로 저장해 올리면 된다.

6. 대회 전 작업과 대회 기간 작업

대회 전(2026-11-05)설계 문서와 작업 계획 문서, Liner Platform 플레이그라운드에서 해 본 검색 2회. 코드는 없었다. 제작자의 기존 강의 자료는 시험 입력으로만 썼고 제출물에 넣지 않았다.
대회 기간(11-12 ~)코드, 자동 시험, 측정 도구, 배포, 문서 전부. 설계와 달라진 점: PDF 지원 추가, 정답을 심은 가상 자료로 측정 방식 변경, 재검색과 숫자 대조 추가, Deep Research 재조사는 만들지 않음.
