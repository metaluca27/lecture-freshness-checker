# 대회 전 작업과 대회 기간 작업의 구분

대회 규정에 따라, 대회 전에 있던 것과 대회 기간(2026-11-12 ~ 11-25)에 새로 만든 것을 나눠 적는다. 이 저장소의 커밋 기록과 맞춰 볼 수 있다.

## 대회 전에 있던 것

| 무엇 | 언제 | 이 저장소에서 |
|---|---|---|
| 설계 문서 | 2026-11-05 | `docs/design.md`에 사본을 그대로 넣었다. 첫 커밋(11-12)에 들어 있다. |
| 작업 계획 문서 | 2026-11-05 | 저장소에 넣지 않았다. 작업 순서와 시험 사례를 적은 문서이고 코드는 없다. |
| Liner Search 시험 2회 | 2026-11-05 | Liner Platform의 플레이그라운드 화면에서 검색어 두 개를 넣어 본 것이다. 코드는 쓰지 않았다. 결과는 설계에 반영했다. |
| 제작자의 기존 강의 자료 | 2026-11 초 | 검사기의 입력으로 시험할 때만 썼다. 저장소에 넣지 않았다. |

대회 전에는 이 검사기의 코드가 한 줄도 없었다.

설계 문서에는 "자료 하나를 다시 확인하는 데 2시간 이상"이라고 적혀 있다. 대회 기간에 제작자가 다시 떠올려 보니 약 50분이었다. 설계 문서는 대회 전 기록이라 고치지 않고 두었고, README와 기획서에는 50분으로 적었다.

## 대회 기간에 새로 만든 것

이 저장소의 코드, 시험, 측정 도구, 문서 전부다. 첫 커밋은 2026-11-12 16:31이다.

| 날짜 | 한 일 |
|---|---|
| 11-12 | 저장소 만들기, Liner API 실제 동작 시험과 기록(`docs/api-notes.md`) |
| 11-13 | 출처 등급, 근거 대조, 최종 판정 규칙, PPT 해석, 본문 읽기, Liner 호출, 검사 흐름, 워커 경로, 진행 관리, 화면, 그림 읽기 |
| 11-15 | PDF 지원, 가상 자료 측정 도구, 재검색, 숫자 대조, 배포 |

설계 문서와 달라진 점도 대회 기간에 생긴 것이다.

- 설계에서는 PDF를 만들지 않기로 했으나 추가했다.
- 설계에서는 제작자가 직접 판정한 정답지 20개로 재기로 했으나, 정답을 미리 심어 둔 가상 자료로 재는 방식으로 바꿨다(`docs/extension-case.md`).
- 설계에 없던 재검색, 숫자 대조, 사용자 게시판 글 제외를 넣었다.
- 설계의 재조사(Deep Research Agent API)는 만들지 않았다.

## 남이 만든 것

| 무엇 | 어디에 | 라이선스 |
|---|---|---|
| JSZip 3.10.1 | `web/vendor/jszip.min.js` | MIT 또는 GPLv3 |
| PDF.js 4.10.38 | `web/vendor/pdfjs/` | Apache-2.0 (글꼴 자료는 폴더 안의 라이선스 파일 참고) |
| Wrangler, pdfjs-dist, jszip | `package.json`의 개발용 의존성 | 각 패키지의 라이선스 |

이 밖의 코드는 직접 썼다.

## 만드는 데 쓴 도구

코드와 문서를 쓰는 데 AI 코딩 도구(Claude Code)를 썼다. 무엇을 만들지, 어떤 측정 결과를 받아들일지, 무엇을 공개할지는 제작자가 정했고, 실제 강의 자료로 돌려 본 결과를 보고 고칠 점을 정했다.
